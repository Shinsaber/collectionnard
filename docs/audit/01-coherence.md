# Livrable 1 — Cohérence du projet

> Audit réalisé le 2026-10-11 sur le commit `279efc4` (branche `main`), plus les fichiers non suivis
> (`CLAUDE.md`, `flake.nix`, `.envrc`, `docs/`, `.claude/`).
> Lecture seule. Chaque constat est étiqueté **constaté** (vérifié dans le code ou par une commande)
> ou **supposé** (à confirmer par le mainteneur).
> Gravités : **C** critique · **H** haute · **M** moyenne · **B** basse.

## Résumé

Le projet est globalement cohérent sur son cœur : les 42 opérations d'`api/openapi.yaml`
correspondent exactement aux 42 routes de `Router()`, les 16 opérations « admin » sont bien dans
le groupe `RequireAdmin`, et les 41 appels du client front visent des routes existantes. Les écarts
se concentrent sur quatre zones :

1. **Documentation historique non mise à jour** : `Collectionnard.md` décrit encore
   `AttributeDefinition` et des relations à source/cible uniques ; `les.collection.md` garde un TODO
   déjà traité ; les versions affichées (README, §9) ne correspondent plus au `package-lock.json`.
2. **Contrat OpenAPI partiellement fictif** : paramètre `attributes[champ]`, tri par
   `attributes.titre`, fusion des attributs à la mise à jour, expiration JWT « 24 h » : tout cela est
   spécifié mais pas implémenté.
3. **Extensions `x-*`** : `slider` documenté mais inexistant, `x-order` absent du seed, et une
   logique de « label d'item » codée en dur dans 6 fichiers alors que la règle du projet interdit les
   champs métier en dur.
4. **Outillage** : `flake.nix` non suivi par git (donc `nix develop` échoue), Node 20 (EOL) dans
   le Dockerfile vs Node 22 dans le flake, Go 1.22 (EOL) dans `go.mod`/Dockerfile vs Go 1.26 dans le
   flake.

Le schéma SQL permet le modèle BD/Manga **sans modification** ; les ajustements nécessaires sont
côté front (détection du label) et côté seed (convention de nommage des champs).

La contrainte `UNIQUE (relation_type_id, source_item_id, target_item_id)` l'interdit avec un seul RelationType `created_by`. Préférence : plusieurs RelationTypes, ou `role` en tableau ?
- **Q4 — Sémantique de `PUT /items/{id}`.** Remplacement complet (comportement actuel) ou fusion (comportement documenté) ?
- **Q5 — `attributes[champ]` et `sort=attributes.x`.** Les retirer de la spec maintenant, ou les garder comme contrat cible de la Phase 2 « recherche avancée » (en les marquant « non implémenté ») ?
- **Q6 — Langue de l'interface.** `x-labels` fournit `en` partout mais le front est figé sur `fr`. Le choix de langue est-il prévu (Phase 2/3) ou faut-il arrêter de maintenir `en` dans les seeds ?
